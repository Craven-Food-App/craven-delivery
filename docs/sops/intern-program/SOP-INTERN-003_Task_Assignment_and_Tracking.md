# SOP-003: Daily Task Management & Time Tracking

**Document ID:** SOP-INTERN-003  
**Version:** 1.0  
**Effective Date:** December 18, 2025  
**Department:** Human Resources / Management  
**Process Owner:** Hiring Manager  
**Review Frequency:** Quarterly  

---

## 1. PURPOSE

This SOP defines how to assign, track, and manage tasks for interns throughout their program, ensuring clear expectations, accountability, and learning opportunities.

---

## 2. SCOPE

**Applies to:**
- Hiring Managers
- Mentors
- Project Leads
- Interns

**Covers:**
- Task creation and assignment
- Task tracking and updates
- Deliverable submission
- Task approval and feedback
- Time logging

---

## 3. TASK TYPES

| Type | Description | Typical Duration | Examples |
|------|-------------|------------------|----------|
| **Onboarding** | Initial setup and training tasks | 1-4 hours | Complete security training, read handbook |
| **Training** | Skill development activities | 2-8 hours | Complete React tutorial, attend workshop |
| **Project** | Contribution to team projects | 8-40 hours | Build feature, create design mockup |
| **Administrative** | Program-related admin tasks | 0.5-2 hours | Submit timesheet, complete evaluation |
| **Development** | Personal growth activities | 2-6 hours | Research topic, write blog post |

---

## 4. TASK PRIORITY LEVELS

| Priority | Description | Response Time | Examples |
|----------|-------------|---------------|----------|
| **Urgent** | Critical, blocking work | Start immediately | Production bug, urgent client request |
| **High** | Important, time-sensitive | Start within 24 hours | Sprint deliverable, deadline approaching |
| **Medium** | Standard priority | Start within 3 days | Regular feature work, documentation |
| **Low** | Nice-to-have, flexible timing | Start when capacity allows | Refactoring, exploratory work |

---

## 5. PROCEDURE

### PART A: CREATING & ASSIGNING TASKS

#### Step A1: Create New Task

**Who:** Manager, Mentor, or Project Lead  
**When:** As needed  
**Time:** 5-10 minutes per task

1. Log in to Manager Portal
2. Navigate to **My Interns** > [Intern Name]
3. Click **Tasks** tab
4. Click **Assign New Task**
5. Fill out task details:

```yaml
Task Title: [Clear, action-oriented title]
  Example: "Implement user login validation"
  Not: "Login stuff"

Description: [Detailed explanation]
  - What needs to be done
  - Why it's important
  - Context/background
  - Definition of done

Category: [Select one]
  - Onboarding
  - Training
  - Project
  - Administrative
  - Development

Priority: [Select one]
  - Urgent
  - High
  - Medium
  - Low

Due Date: [Select date]
  - Consider intern's capacity
  - Account for learning curve
  - Allow buffer time

Estimated Hours: [Number]
  - Be realistic
  - Include learning time
  - Discuss with intern if unsure

Related Resources: [Links/attachments]
  - Documentation
  - Examples
  - Design files
  - Reference materials

Dependencies: [List any blockers]
  - Other tasks that must be completed first
  - People who need to provide input
  - External factors

Success Criteria: [How will we know it's done?]
  - Specific, measurable outcomes
  - Quality standards
  - Acceptance criteria
```

6. Click **Assign Task**
7. System automatically:
   - Notifies intern via email and in-app
   - Adds to intern's task list
   - Creates activity log entry
   - Starts tracking

**Expected Result:** Task assigned, intern notified

---

#### Step A2: Task Assignment Best Practices

**Guidelines for Effective Task Assignment:**

✅ **DO:**
- Start with small, achievable tasks
- Gradually increase complexity
- Provide clear instructions
- Include learning resources
- Set realistic deadlines
- Make yourself available for questions
- Celebrate completions

❌ **DON'T:**
- Assign critical-path work too early
- Give vague instructions
- Set unrealistic deadlines
- Assume prior knowledge
- Leave intern blocked
- Forget to provide feedback

**Task Sizing Guide:**
```
Week 1-2:   Small tasks (2-4 hours each)
Week 3-4:   Medium tasks (4-8 hours each)
Month 2:    Larger tasks (8-16 hours each)
Month 3+:   Project work (16-40 hours each)
```

**Balanced Task Mix:**
```
40% - Project work (real contributions)
30% - Learning/training
20% - Shadowing/observation
10% - Administrative
```

### PART B: INTERN TASK WORKFLOW

#### Step B1: Intern Receives Task

**Who:** Intern  
**When:** When task assigned  
**Time:** 5 minutes

1. Receive notification (email + in-app)
2. Log in to Intern Portal
3. Navigate to **My Tasks**
4. Review new task:
   - Read description carefully
   - Check due date
   - Review resources
   - Note estimated hours

5. If task is clear:
   - Click **Start Task**
   - Status changes to "In Progress"
   - Begin work

6. If task is unclear:
   - Click **Request Clarification**
   - Type questions
   - Submit to manager
   - Wait for response before starting

**Expected Result:** Intern understands task and begins work

---

#### Step B2: Work on Task

**Who:** Intern  
**When:** Task in progress  
**Time:** Varies

**Daily Workflow:**
1. Review task details
2. Work on task
3. Log time spent:
   - Click **Log Time** on task
   - Enter hours worked
   - Add brief description of work done
   - Click **Save**

4. Update task status if needed:
   - **In Progress** - Actively working
   - **Blocked** - Waiting on something
   - **Ready for Review** - Completed, needs review

5. If blocked:
   - Click **Mark as Blocked**
   - Explain blocker
   - Tag person who can unblock
   - System notifies manager

**Communication Best Practices:**
- Ask questions early
- Provide progress updates
- Flag issues immediately
- Over-communicate rather than under-communicate

**Expected Result:** Steady progress on task

---

#### Step B3: Submit Deliverable

**Who:** Intern  
**When:** Task completed  
**Time:** 10-15 minutes

1. Navigate to task in Intern Portal
2. Click **Submit Deliverable**
3. Fill out submission form:

```yaml
Deliverable Type:
  - Document
  - Code (link to PR)
  - Presentation
  - Report
  - Design
  - Other

Deliverable Location:
  - Upload file, OR
  - Provide link (GitHub PR, Figma, Google Doc, etc.)

Completion Notes:
  - What was accomplished
  - Any challenges encountered
  - Questions or concerns
  - Areas where feedback is needed

Actual Hours Spent: [Number]
  - Be honest
  - Include all time (research, work, debugging)

Lessons Learned:
  - What did you learn?
  - What would you do differently?
  - What was most challenging?
```

4. Click **Submit for Review**
5. Task status changes to "Under Review"
6. Manager receives notification

**Expected Result:** Deliverable submitted for review

---

### PART C: MANAGER REVIEW & FEEDBACK

#### Step C1: Review Deliverable

**Who:** Manager or Mentor  
**When:** Within 24-48 hours of submission  
**Time:** 15-30 minutes

1. Receive notification of submission
2. Navigate to **My Interns** > [Intern Name] > **Tasks**
3. Click on task with status "Under Review"
4. Review deliverable:
   - Check against success criteria
   - Evaluate quality
   - Test functionality (if applicable)
   - Review code (if applicable)

5. Make decision:
   - **Approve** - Meets standards
   - **Request Changes** - Needs improvement
   - **Reject** - Does not meet requirements (rare)

**Expected Result:** Deliverable reviewed

---

#### Step C2: Provide Feedback

**Who:** Manager or Mentor  
**When:** During review  
**Time:** 10-15 minutes

**If Approving:**
1. Click **Approve Deliverable**
2. Provide positive feedback:

```
Great work on [specific accomplishment]!

Strengths:
- [What was done well]
- [Positive observations]
- [Skills demonstrated]

Impact:
- [How this helps the team/company]

Next Steps:
- [What comes next]
- [How to build on this]

Keep up the excellent work!
```

3. Click **Submit Feedback**
4. Task status changes to "Completed"
5. Intern receives notification

**If Requesting Changes:**
1. Click **Request Changes**
2. Provide constructive feedback:

```
Thanks for your work on this task. I've reviewed it and have
some feedback for improvements.

What's Working:
- [Positive aspects]

Areas for Improvement:
- [Specific issue 1]
  - Why it's an issue
  - How to fix it
  - Resources to help

- [Specific issue 2]
  - Why it's an issue
  - How to fix it
  - Resources to help

Please make these changes and resubmit. Let me know if you
have questions!
```

3. Click **Submit Feedback**
4. Task status changes to "In Progress"
5. Intern receives notification with feedback

**Feedback Best Practices:**
- Be specific, not vague
- Focus on behavior, not person
- Provide examples
- Suggest solutions
- Balance positive and constructive
- Respond promptly
- Be encouraging

**Expected Result:** Clear, actionable feedback provided

### PART D: TIME TRACKING

#### Step D1: Log Time Daily

**Who:** Intern  
**When:** Daily or weekly  
**Time:** 5 minutes per day

1. Log in to Intern Portal
2. Navigate to **Time Logs**
3. Click **Log Time**
4. Fill out time log:

```yaml
Date: [Select date]
Hours Worked: [Number, max 24]
Task: [Select from dropdown, or "General"]
Activity Type:
  - Project Work
  - Training
  - Meetings
  - Research
  - Documentation
  - Other

Description: [Brief description of work]
  Example: "Implemented login validation, debugged test failures"
```

5. Click **Save Time Log**
6. Repeat for each day

**Time Logging Rules:**
- Log time daily (don't wait until end of week)
- Be honest and accurate
- Round to nearest 0.25 hours
- Include all work-related time
- Don't log breaks or lunch
- Don't exceed approved hours per week

**Expected Result:** Accurate time logs submitted

---

#### Step D2: Manager Approves Time Logs

**Who:** Manager  
**When:** Weekly  
**Time:** 10 minutes per intern

1. Navigate to **My Interns** > **Time Logs**
2. Review unapproved time logs
3. For each log:
   - Verify hours are reasonable
   - Check against task progress
   - Ensure within approved hours

4. If approved:
   - Click **Approve**
   - Log is locked

5. If issues:
   - Click **Request Correction**
   - Explain issue
   - Intern revises and resubmits

**Approval Deadline:** Within 7 days of submission

**Expected Result:** Time logs approved weekly

---

### PART E: TASK MONITORING & MANAGEMENT

#### Step E1: Monitor Task Progress

**Who:** Manager  
**When:** Daily/Weekly  
**Time:** 10-15 minutes

1. Navigate to **My Interns** > **Dashboard**
2. Review task metrics:
   - Tasks in progress
   - Tasks overdue
   - Tasks blocked
   - Completion rate

3. Check for issues:
   - Overdue tasks
   - Blocked tasks
   - No progress updates
   - Excessive time logged

4. Take action:
   - Follow up on overdue tasks
   - Unblock blocked tasks
   - Adjust deadlines if needed
   - Provide support

**Expected Result:** Proactive task management

---

#### Step E2: Weekly Task Review Meeting

**Who:** Manager + Intern  
**When:** Weekly  
**Time:** 30 minutes

**Meeting Agenda:**
1. Review completed tasks
   - Celebrate wins
   - Discuss learnings

2. Review in-progress tasks
   - Check progress
   - Identify blockers
   - Adjust priorities

3. Assign new tasks
   - Based on capacity
   - Aligned with learning goals
   - Mix of challenge levels

4. Discuss challenges
   - What's difficult?
   - What support is needed?

5. Set goals for next week

**Expected Result:** Aligned on priorities and progress

---

## 8. TROUBLESHOOTING

| Issue | Cause | Solution |
|-------|-------|----------|
| Intern not starting tasks | Unclear instructions | Provide more detail, schedule kickoff call |
| Tasks taking too long | Underestimated complexity | Adjust estimate, provide more support |
| Tasks consistently overdue | Too much assigned | Reduce workload, check for blockers |
| Intern not logging time | Forgot or unclear process | Send reminder, review process |
| Poor quality deliverables | Insufficient guidance | Provide examples, increase check-ins |
| Intern seems stuck | Afraid to ask for help | Create safe environment, proactive check-ins |
